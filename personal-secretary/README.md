# Gurukul Personal Secretary

A private Custom GPT action platform for quote-and-confirm personal-secretary workflows.

Every workflow must first return an exact short-lived signed quote. Execution requires explicit confirmation with the unchanged quote token, and repeated execution of the same quote is idempotent for the life of the running service instance.

## Approved workflows

### Haircut booking

The existing haircut workflow remains intentionally narrow:

- Business: Del Ray Barbershop, 2496 Victoria Drive, Vancouver
- Service: Buzzcut and Beard Trim
- Barber: Scotty
- Eligible days: Thursday first, then Friday
- Eligible time: 2:00 PM or later, America/Vancouver
- Search window: up to 2 weeks
- Payment: booking is allowed only when Square shows CAD $0 due today

The GPT cannot use this service to book a different business, barber, service, or paid checkout.

The public haircut API is preserved:

- `POST /v1/availability`
- `POST /v1/book`

### Bakery delivery sandbox

The bakery workflow uses the same quote-and-confirm platform with a deterministic fake provider. It cannot place a real order or charge payment.

- Merchant: `Sandbox Bakery`
- Products: configured SKU catalog only
- Delivery: configured destination references only, never raw addresses
- Delivery windows: configured sandbox windows only
- Quantity: per-product and total item limits
- Spending: total estimated amount must be within the configured CAD limit
- Tip: allowed only within the configured cap

Bakery endpoints:

- `POST /v1/bakery/delivery-quote`
- `POST /v1/bakery/order`

The generic workflow endpoints are also available for registered workflows:

- `POST /v1/workflows/{workflowId}/quote`
- `POST /v1/workflows/{workflowId}/execute`

## Flow

1. A quote endpoint validates user-controlled fields and asks the workflow provider for a proposal.
2. The API returns the exact proposal and a short-lived HMAC-signed quote token.
3. The GPT presents the proposal for approval and preserves the quote token exactly.
4. An execute endpoint accepts only that unmodified quote and requires `confirm: true`.
5. The workflow revalidates the signed proposal before calling its provider.
6. The API returns a normalized result without exposing internal tokens or secrets.

For haircut booking, execution opens a fresh browser session, rechecks the exact slot, verifies the checkout, fills contact details from Render secrets, and submits only when Square still shows CAD $0 due today.

## Security

Never commit contact information or API keys. The runtime requires:

- `SECRETARY_API_KEY`: shared only with the private Custom GPT action
- `SECRETARY_SIGNING_KEY`: server-only HMAC key
- `SECRETARY_PHONE`
- `SECRETARY_FIRST_NAME`
- `SECRETARY_LAST_NAME`
- `SECRETARY_EMAIL`

The first two can be generated by Render. Contact values must be entered as Render environment secrets. They are never returned by the API or intentionally written to logs.

Workflow audit events are structured and redacted. Quote tokens, API keys, contact details, raw addresses, payment data, browser state, cookies, and session material must not be logged or committed.

Bakery delivery currently uses only the fake provider in `src/bakery/fake-provider.js`. Adding a real provider should require:

1. Implementing the provider interface used by `src/bakery/workflow.js`: `createProposal(request, config)` and `placeOrder(proposal)`.
2. Keeping merchant, product, delivery, quantity, tip, tax, and spending validation in `src/bakery/domain.js`.
3. Adding sandbox or mocked tests before enabling live execution.
4. Reviewing any real checkout or payment submission separately from the workflow orchestration layer.

## Local test

```bash
cd personal-secretary
npm install
npm run lint
npm test
```

To run the browser service locally:

```bash
npx playwright install --with-deps chromium
export SECRETARY_API_KEY='replace-me'
export SECRETARY_SIGNING_KEY='replace-me-with-a-long-random-value'
export SECRETARY_PHONE='your-number'
export SECRETARY_FIRST_NAME='Harsh'
export SECRETARY_LAST_NAME='Loomba'
export SECRETARY_EMAIL='your-email'
npm start
```

## Render deployment

The root `render.yaml` defines the Docker service `gurukul-personal-secretary-harsh`.

After the branch is merged:

1. Sync the existing Gurukul Blueprint in Render.
2. Enter the four `sync: false` contact values when prompted. For an already-created service, add them manually in its Environment page.
3. Confirm `https://gurukul-personal-secretary-harsh.onrender.com/health` returns `configured: true`.
4. Copy the generated `SECRETARY_API_KEY` from Render for the private Custom GPT action.

## Custom GPT attachment

Create a private GPT named **Personal Secretary**.

1. Paste the contents of `custom-gpt-instructions.md` into Instructions.
2. Add an Action and import:
   `https://gurukul-personal-secretary-harsh.onrender.com/openapi.yaml`
3. Set authentication to API key using the custom header `X-Secretary-Key`.
4. Paste the Render value of `SECRETARY_API_KEY`.
5. Use this privacy-policy URL:
   `https://gurukul-personal-secretary-harsh.onrender.com/privacy`
6. Keep the GPT private.

The booking operation is marked consequential, so ChatGPT should ask for approval before creating the external appointment.
